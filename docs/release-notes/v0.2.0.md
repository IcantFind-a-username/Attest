# attest v0.2.0

## What it says

attest reviews a pull request and publishes only what it can prove. There are four levels and
they never borrow each other's words. **Red** is a defect claim backed by a receipt: a generated
test that fails on the head commit and passes on the merge base, three runs each way, inside a
network-free container, with a bundle anyone can verify offline. **Yellow** is a measured fact
you should look at — the impact scope of an interface change, or, where a repository opens it,
what a call returned on the merge base and what it returns now — with coordinates and the count
of runs behind it, and no claim that it is a defect. **Green** is a structural observation
computed with no model at all. When nothing meets an adjudicator's bar the review says so in one
line, and says how much of the change that silence covers.

Since v0.1.0 the rejection rule reads the exception's frame rather than the statement that
raised it: a head that starts refusing an input the merge base accepted — by a `raise`, a builtin
or a library call alike, on a line the change wrote — is a behaviour change whose intent the
reviewer cannot read, shown as a yellow line where the value switch is on and never as a red
receipt, unless the base tree's own tests use that input, in which case it is published red and
worded *intent to confirm*. A return-annotation-only change no longer makes a yellow (a) line,
and a container value on the yellow line is shown by the first element that moved. A warning is
never a rejection: a head that raises a `Warning` subclass where the merge base returned -- under
its own `filterwarnings = error` or a filter the probe installed -- certifies nothing and drawers
nothing, and a probe whose setup reaches for `warnings`, `sys.modules`, a mock, the environment or
an attribute of an imported module is refused before it runs.

## The numbers

<!-- release-numbers:begin -->
On **44 merged pull requests** of **13 open-source Python libraries** attest said **7 lines** on
6 of them; the owner adjudicated each by hand: **0 useful, 0 true but not actionable, 0 wrong,
7 pending adjudication** (`docs/receipts.md`, generated from the reports' own columns; four
further lines, three of them a deprecation warning read as a defect, were withdrawn by the
warning rule before this release). On **forty injected forward defects** of eight public
libraries the crash-class recall is **9 of 40 — 22.5%** (Wilson 95% [12.3%, 37.5%]; the run
certified ten, and one probe that had replaced an attribute of the module under test was
withdrawn), with **0** of the forty read as a behaviour change with unknown intent under the new
rejection rule. On the reversed held-out
SWE-bench slice, 5 of 25 — 20.0%, [8.9%, 39.1%]. Thirteen of thirteen red-team attack classes
are marked and never certified. A review costs about $0.11 to $0.22 and is hard-capped at
`budget-usd`, $1.00 by default.

## Limits

Python only: Python, pytest, Linux containers, interpreters 3.10–3.13; anything else gets one
line naming the reason and exit 0. A silence is an abstention, never a true negative — nothing
here licenses *found nothing, so it is fine*. Whether a rejection the head newly raises was meant
is a question the reviewer hands to the author rather than answers: it says exactly what it
measured and asks. Recall is low and comes from two corpora with two denominators, neither of
them natural traffic. Not on PyPI; installed only as a GitHub Action pinned to this tag.
