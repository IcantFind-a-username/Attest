# attest v0.3.0

## What it says

attest reviews a pull request and publishes only what it can prove. There are four levels and
they never borrow each other's words. **Red** is a defect claim backed by a receipt: a generated
test that fails on the head commit and passes on the merge base, three runs each way, inside a
network-free container, with a bundle anyone can verify offline. **Yellow** is a measured fact
you should look at — the impact scope of an interface change, or, where a repository opens it,
what a call returned on the merge base and what it returns now — with coordinates and the count
of runs behind it, and no claim that it is a defect. **Green** is a structural observation
computed with no model at all. When nothing meets an adjudicator's bar the review says so in one
line, and says how much of the change that silence covers.

Since v0.2.0 the reviewer can no longer write to the repository it reviews: a project that sets
`[tool.ruff] fix = true` had the tier-0 lint rewrite its own anchored file, and the lint is run
`--no-fix` now whatever the project configures — the one such path, and it was reachable on
shipped reviews only because the same window made the lint channel reachable at all. Two
environment losses are repaired: a project that generates its version file at build time can be
imported from the reviewed worktree, and a merge base that returns a closure or a context manager
records stably instead of being refused for an object address that changes every run. The probe —
the one call that chooses what to execute on both revisions — is told more and asked differently:
the values the repository's own tests assert, the comparisons and guards the change moved, the
callers of the changed symbol resolved through the import that bound the name rather than by
matching its spelling, and, since D-248, it thinks. A value line now carries a runnable Python
block instead of only a returned value, and the run row says which stage bought what.

## The numbers

<!-- release-numbers:begin -->
On **68 merged pull requests** of **19 open-source Python libraries** attest said **14 lines** on
10 of them; the owner adjudicated each by hand: **4 useful, 3 true but not actionable, 0 wrong**,
with the 7 lines of the third batch **pending adjudication** (`docs/receipts.md`, generated from
the reports' own columns). On **forty injected forward defects** of eight public libraries the
crash-class recall is **13 of 40 — 32.5%** (Wilson 95% [20.1%, 48.0%]) under the default probe
call chosen in D-248, with the boundary class at 2 of 13. On the reversed held-out SWE-bench
slice, 5 of 25 — 20.0%, [8.9%, 39.1%] — **not re-measured this release**. Thirteen of thirteen
red-team attack classes are marked and never certified. On the forty, a case costs a median
$0.046 and $0.076 at the 95th percentile, $0.024 to $0.182 across them; every review is
hard-capped at `budget-usd`, $1.00 by default.

## Limits

Python only: Python, pytest, Linux containers, interpreters 3.10–3.13; anything else gets one
line naming the reason and exit 0. A silence is an abstention, never a true negative — nothing
here licenses *found nothing, so it is fine*. Whether a rejection the head newly raises was meant
is a question the reviewer hands to the author rather than answers.

**Recall on the forty has plateaued between 11 and 14.** Six runs and four changes across two
releases have not moved it out of that band, and the mechanism is named: the wall is the
value-class rule, not the search. A probe reaches the changed behaviour and the drawer refuses the
observation because nothing in the base tree pins the value it would assert — the boundary class
sits at 2 of 13 while the probes reached the boundary in 11 of those 13. The context work of
D-245/D-246 repaired real holes (caller snippets 34 → 51, with 0 real callers still missing) and
did not move the number; the shared package block that the ordering rule was written for has
**never been built** on any measured run, so its lever has had no chance to act
(`docs/acceptance/2026-09-14-index-repair.md` §4). There is no `D-247`: the decision numbering
skips it.

**The default probe call changed, so this release's forty is not the same ruler as v0.2.0's.**
The figure moved from 9 of 40 to 13 of 40 and that is not a demonstrated gain of four cases: one
re-run of this corpus moves about ±2 on its own, the instrument changed underneath the measurement
(D-248), and part of the v0.2.0 figure was a replay withdrawal rather than a run. The three arms
were indistinguishable on recall (12, 14, 13 of 40) and the default was chosen on price.

The three batches of real pull requests were reviewed under the **previous** probe call and are
unmeasured under this one. No precision figure exists at any level: nothing has ever been
certified on natural traffic, so precision is undefined. Every control number is at K=4 while the
shipped `samples` is 5. Naming any model in `probe-model` other than the three the pricing table
carries is running a configuration that has never been measured on any corpus. Not on PyPI;
installed only as a GitHub Action pinned to this tag.
