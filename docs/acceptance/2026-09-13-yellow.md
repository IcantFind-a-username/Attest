### 2.1 The number moved, and the cause is on the record

The 2026-09-08 report recorded **2 of 68** controls and **1 of 11** forward pairs. Today the same
scan on the same trees at the same shas gives **1 of 68** and **0 of 11** — one note removed from
each population, both with the identical reason string `3 call sites in 3 files and no test names
this function`.

The code did not drift by accident. `482b6a5` — **D-174's *"a call site is what the name resolves
to"*** — **is not an ancestor of `dccd076`**, the commit that recorded the 2026-09-08 evidence.
That measurement was taken before the fix. D-174 made call-site resolution stricter, and the
three apparent call sites in the removed note no longer resolve to that function.

So this is not a regression and not a new measurement of a changed level: **it is the first
measurement of yellow (a) taken after D-174**, and the number it replaces was taken before it.
The 2026-09-08 report is not corrected — it is append-only evidence and it was right about the
code it ran on.

**This improves the backlog's standing P2 concern.** That item reads *"a4 meets the 3% control
ceiling by one event; 3 of 68 would be 4.4% and would fail."* The margin is now **two** events,
not one.

### 2.2 The one control note, analysed

The surviving control note is `9 call sites in 2 files and no test names this function`.

**It is true**, on the same reading as §1.1: the function is changed, nine call sites resolve to
it, no test names it. **It is not a defect claim**, and the level does not make one.

**Can it be fixed?** Only by raising the threshold — a4 fires at ≥3 call sites in ≥2 files — and
that is a level-policy change, not a bug fix. The owner's rule for this phase is that a fix must
be a real fix and not a loosening; raising a threshold to make a true statement stop being made
is a loosening. **It is therefore not fixed, and it is recorded as a known limitation**: on a
population of commits nobody had to fix, yellow (a) speaks about **1 in 68** of them, and what it
says is true and unimportant. That is the level's noise floor and the README carries it.

## 3. The finding this census was not looking for

**Six of the eleven self-reviews published bare prose where the contract requires a line.**

```
DEFER: verification deferred: probe reported no observation on base (3 candidates)
```

No `[level]` marker. No `file:line`. No count of change units read. Mainline §1 condition 7 says
*every author-visible line* obeys the output contract, and `review.output_contract`'s own
adjudicator **refuses this line** — it was published anyway, because nothing adjudicated it.

D-190 put the **five refusals** on a contract line and left an ordinary deferral on the old path.
The six are PRs #14, #15, #18, #20, #21 and #22 — and the last three are **this task's own pull
requests**, so this is a live defect and not a pre-D-190 artefact.

**Fixed here as D-201**, in the shape the owner chose: a fifth silence verdict, the same register,
the class name where the refusal name goes.

```
[silent] read 2 of 7 units; deferred (probe-no-observation): the probe recorded no
observation on the merge base, so no difference between the two revisions could be
measured; nothing was verified; ledger: https://…/actions/runs/42; $0.3112, 41.8s.
```

Four classes, each with the product's own fixed sentence chosen by the class name — never the
DEFER reason, which can quote a traceback, a runner path or a build log. A test drives a reason
carrying `ANTHROPIC_API_KEY=…`, a traceback and `/home/runner` through the whole path and pins
that none of it reaches the line.

  has never been shown to find a defect.

- **That the control population is a good one.** These 68 are `G-NULL-001a`'s controls and carry
  that study's own qualification rule; the backlog's P2 item about that rule still stands.
