# 契约上下文正确性与代价（D-257）

## 结论

本轮修复了已复现的局部测试上下文误归因。代价是，当前严格子集无法使用现有
语料中的契约探针，三个实验增益不再发布。**这是正确性修复，不是召回提升；
也没有证明所有隐式上下文都已安全。** 默认仍为 `attest.intent.v5.1`，实验规则
仍为 `attest.intent.v6.1`，不切换默认、不付费、不推送、不发布版本。

用户在“下一轮只做契约上下文正确性”的建议后明确回复“做”。本轮不实施探针
选择策略修改，也不开展付费独立评估。

## 2. 最小修复及边界

生成器在派生候选前检查上下文；观察器在认证时重新读取 base/head，各自运行相同的
确定性检查，不接收生成器的“可信”标志。不支持的上下文保留来源和行号，令契约
`flow_bound=False`、`admitted=False`。现有内核仍独立核对字段一致性与 admission。
head 新增不支持的上下文时，基线契约也不能通过 `standing_at_head`。

支持范围很小：

- 祖先 conftest 只允许空文件、文档字符串或 `pass`；代码、读取失败、解析失败、
  大文件和符号链接均拒绝，不猜测它是否“看起来无关”。
- 测试模块和类中的 setup/teardown、pytest hook/plugin 声明、未知装饰器、
  非平凡类构造、执行语句、可执行默认值/注解均拒绝。
- 参数化行收紧为字面量，装饰器必须来自此前未重绑的规范 `import pytest`。
  参数行中的构造调用也拒绝；合法正例改用字面量字段，在断言处构造期望对象。
  原构造行测试保留为拒绝回归测试，没有删除旧形状。额外参数不能执行表达式或调用回调。
  `ids` 只允许字面量 ID 序列或 `None`，`indirect` 只允许 `False`。
- 普通导入未被当作无副作用的证明。**传递导入、环境插件、前序测试遗留状态仍不追踪。**
  此检查通过只代表没有发现这些局部拒绝条件，不代表完整运行上下文已证明。
  产品路径也没有通过实际收集和执行原测试节点来证明该断言确实运行；本轮合成实验对
  原测试的执行属于评估证据，不会自动变成产品认证能力。

离线 bundle 验证仍是对既有观察记录的重判，不会从仓库源码重建测试上下文。
本轮没有增强或改变这个保证。实验规则的默认启用/推广仍被阻止。
本轮也没有修改既有的字面值证据与其他意图规则；这些结果不能替那些路径提供新的
正确性保证。

## 4. 独立评审与验证

一次独立评审复现一个高优先级问题：整条 `parametrize` 装饰器被豁免，`ids=install()`
能替换函数。实现者补充完整差分/认证链路复现，确认修复前错误接受；修复后拒绝。
初次修复只限制了关键字参数，收尾时发现同一根因仍覆盖位置参数 `[install()]`，
完整链路 RED 确认仍会接受错误收据。因此停止已被取代的门禁，收紧为字面量行并核对
装饰器的实际导入绑定；补测假绑定与重绑定。评审原文和 RED 保留，未启动第二轮评审。
最后修复由实现者复核，不冒称已经再独立评审。

新上下文测试复用场景构造和完整差分链路，setup 较多是为了断言原测试确实通过、
读取器拒绝和最终认证结果，而不是只验证对象构造；不另写执行或序列化工具。

基线定向套件 90 项通过。最终定向套件 135 项通过，Ruff 与 Mypy 通过。
初次修复套件曾将 conftest 的“未进入观察器”错误期待为“观察器拒绝”；保留失败日志，
改为分别断言执行器早期拒绝与独立读取器拒绝，不将未执行计作安全认证。

首次全量门禁在 `44cb41e` 上运行 619 秒后中止，退出码 2，不是通过。16 个 CLI
测试的子进程均因 `ModuleNotFoundError: attest` 失败。editable 安装的 `.pth`
带隐藏标记，Python 跳过该路径文件，与 D-256 的环境现象相同；没有证据确定标记来源。
先用 `PYTHONPATH=src` 对一个失败项复现环境差异；停止门禁后清除该文件的隐藏标记，
内容不变，再以普通命令重跑全部 16 个失败项，均通过。未修改产品代码或削弱测试。
首次日志及 `gate-result.json` 永久保留，r2 在同一提交上重新运行全量门禁。

r2 运行 137 秒时同一隐藏标记恢复（起始 flags=64，结束 flags=32832），因此提前
中止，退出码 2，也不是通过。r3 显式设置 `PYTHONPATH` 为原 editable 文件已经指向的
本仓库 `src`，稳定开发源码导入；不再修改文件标记，不使用它验证发行包安装。
r3 运行 2,201 秒后因参数行回调仍被接纳而停止，退出码 2；

## 5. 架构判断与后续

不能靠不断增加静态排除规则维持契约供给，也不能为保留三个案例放松绑定。
本轮结果支持下一步先设计**带真实测试上下文的契约见证**：绑定具体测试节点、
实际入口/receiver/输入和断言、环境与源码身份，并由可信观察器采集、内核裁定。
优先复用仓库已有测试节点，保留实际 fixture/setup 的执行，而不是把函数调用从上下文
中摘出来后仍声称它等同于原测试。测试通过、差分成立或定位重合本身都不能替代上述绑定。
是否足以恢复良性 fixture 场景，必须先用小型原型和合理变化反例检验。
这只是下一项决策建议，本轮未新增执行方式、认证类型、CLI 或产品表面。

探针选择遮蔽问题保持原样。付费 forty、独立评估和 1.0.0 发布都不由本轮结果自动授权。
必要时可通过新的 revert 提交撤销 `2dc8823` 与 `e540e0d` 的局部检查；
不要删除历史工件或重写提交。生产默认未启用实验规则。
