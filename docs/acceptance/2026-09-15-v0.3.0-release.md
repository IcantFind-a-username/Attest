## 2. The one thing that failed, and what it was

**The red-team matrix failed its first dispatch of this window, on the positive control — not on an
attack.** Run [34784037696](https://github.com/IcantFind-a-username/Attest/actions/runs/34784037696)
reported `FAIL: 13 attack fixture(s), 1 control` with every one of the thirteen attack rows `ok`
and this row deferred:

```text
FAIL positive control: a real regression: deferred [intent: behavior change confirmed,
intent unknown: head raises IndexError from a call or expression on a changed line;
no rejected input could be identified from the test's literals]
```

The matrix was last dispatched on 2026-09-12, **before `attest.intent.v5`**. The `v0.2.0` checklist
accepted that unre-dispatched, on the argument that D-232 adds no path by which an attack could
certify. That argument was about the attack rows and it held. It did not cover the control, whose
fixture made head raise on a line the change wrote — exactly the shape D-232 sends to the drawer.
By the matrix's own rule (*a matrix of refusals with a dead control proves nothing works*) the run
could render no verdict about the isolation boundary.

The control was repaired to the class D-232 leaves to red and the mutation corpus certifies: the
base coerces `None`, head coerces `str` instead, the changed line executes, and the `TypeError` is
raised on a `return` both trees write identically, so no written line is on the exception's path.
**No attack fixture, verdict rule or threshold moved.** The pin in
`tests/release/test_redteam_matrix.py` now holds both properties the control needs and records both
times it has broken for a reason unrelated to the boundary (2026-09-07, a value change; 2026-09-13,
a written raising line). Re-dispatched: PASS.

This is the second time the control has been broken by a publication-rule change and found only by
dispatching. **The matrix has to be dispatched in the window that changes the intent rule**, not
argued about; that is the lesson, and it is the reason this release has a matrix run of its own.

## 5. Known gaps, carried into the tag

1. **The third batch is unadjudicated.** Seven of the fourteen lines read `pending`; the README and
   `docs/receipts.md` say so in the same sentence as the verdict counts. Until the owner fills the
   columns there is no adjudicated verdict for the six libraries of batch 3.
2. **The held-out SWE-bench slice was not re-measured** under the D-248 default, or under D-245/246,
   or under D-240. Its figure is the 2026-09-11 one and is labelled with that date everywhere.
3. **The three real-PR batches were all reviewed under the probe call before D-248.** Real traffic
   is unmeasured under what ships.
4. **The shared package block has never been built** on any measured run (`context_strategy` is
   `r01`); the ordering rule D-245 wrote for it has had no chance to act. The free census says it
   would bind on 49 of 68 real pull requests were it built. **There is no `D-247`** — the decision
   numbering skips from D-246 to D-248, and nothing in the repository claims that ID.
5. **No model outside the pricing table's three has been measured on any corpus**, Claude Fable 5.1
   among them. `probe-model` will accept one; doing so runs a configuration with no recall, cost or
   wall-clock figure. README limitation 4 and `docs/github-action.md` both say it.
6. **D-185's old-pytest gap is closed** by D-186 (a project outside the supported interpreter range
   is reported as such rather than as a missing artifact) and is listed here only because it was an
   open gap at `v0.1.0`; the supported range, 3.10–3.13, is unchanged by this release.
7. **External observation of the isolation boundary is still INSUFFICIENT.** Every red-team row is
   observed from inside the product. The matrix says so itself and this release does not change it.
8. **Four commits that the tag will contain carry a vendor trailer, against D-002.**
   `46a5181`, `73eca44`, `e75ac07` and `7f6d352` (2026-09-12 and 2026-09-13) end in a
   `Co-Authored-By:` line naming an assistant and a `Claude-Session:` URL. The commit hook is a
   partial backstop and it did not catch them. **All four are already on `origin/main`**, so the
   only way to remove them is to rewrite published history, which AGENTS.md §7 forbids and which
   would invalidate every merged pull request reference. They are reported here rather than
   repaired: **this is an owner decision**, and the default is to leave them and let the hook be
   tightened separately. No commit made by this work order carries a trailer, and no branch name,
   code comment or document in the release does.
9. **Recall on the forty has plateaued between 11 and 14** across six runs and four changes, and the
   mechanism is the value-class rule rather than the search. The release notes' limits section
   leads with this.
