## Population and construction

- Corpus: SWE-bench Verified, dev slice of the committed split
  [`benchmarks/attest-v2/splits/swebench-verified-v1.json`](../../benchmarks/attest-v2/splits/swebench-verified-v1.json)
  (seed 20260902, 99 dev / 401 held-out).
- Feasibility rule, declared before any run: repositories that install with plain `pip`
  (requests, pytest, pylint); compile-heavy repositories (matplotlib, scikit-learn, astropy)
  and the large pure-Python ones (django, sympy, sphinx, xarray) were not built for budget
  reasons. Within the feasible repositories the instances are the first by id in the dev
  slice. Not outcome-dependent.
- Regression PR shape: base = `base_commit` + gold code patch (fixed); head = base + revert
  of that patch. The gold tests never enter the product path (`hidden-truth.jsonl` is not
  read by the driver's `run`). For pytest's own repository a fixed `_pytest/_version.py` is
  committed beneath both sides because the executor runs from fresh worktrees.
- Controls, built the same way from the same repositories: five test-only (base =
  `base_commit`, head = base + gold *test* patch, no code change) and three docs-only (a
  real docs-only history commit at or before `base_commit`).
- Runner: `scripts/corpus/swebench_pilot.py run <case> --k 4` → `attest.review.ci.run_ci`
  with the real provider, a per-case virtualenv (CPython 3.9.19 for requests and pylint,
  3.11.5 for pytest; 3.8 trips the process guard through `platform`, 3.12 cannot import
  the older projects), a loopback GitHub server, verification timeout 900 s. No product
  code changed for the pilot except the kernel claim bound below.

## Limits

- Eight regressions and eight controls from three repositories is a pilot, not an estimate
  of recall or precision; the held-out slice is reserved for step 13.
- pytest's own repository is "runner is subject": the reviewed pytest becomes the test
  runner, so its interpreter constraints (no `imp` on 3.12) and generated files shape the
  outcome; recorded in the backlog for the executor profile.
- The product's own ledgers (`.attest/corpora/swebench/cases/<case>/repo/.attest/`) hold
  every row; summaries are in `.attest/corpora/swebench/results/`; certified bundles are
  under each case's `.attest/evidence/`.
