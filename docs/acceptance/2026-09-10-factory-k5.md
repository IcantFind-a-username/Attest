# The factory K, measured — 2026-09-10

**Owner instruction 2 of this window**, and owner item 1 of the
[2026-09-09 acceptance](2026-09-09-release-readiness.md) answered *yes*: every empirical number
in this repository was taken at **K=4**, while `action.yml` ships **K=5** and
`ReviewConfig.k_samples` is 5. This report is the first run of the shipped configuration on a
fixed sample.

## 1. The sample, and why it is 27 and not 153

The fixed sample is 153 reviews: 11 forward pairs, 16 held-out crash/exception cases, 58 + 68
null controls. **K moves discovery, not adjudication**, and the 126 controls' K=4 verdicts are
silences — so the 27 reviews where a verdict exists are the minimum sample that can move one.
At the `--budget 1.00` cap the 153-review form is **$153.00**, which does not fit the remaining
cap; the 27-review form reserves **$27.00**, which does.

The 16 held-out cases are **derived, not chosen**. D-158 makes the held-out denominator the
crash/exception class: of the 28 defect cases that ran under the probe generator, 4 certified,
**12 reached a value-class observation** (`value change confirmed` / `constant change confirmed`)
and **12 never reached a classifying observation at all** — so the crash denominator is
`4 + 12 = 16`. The split is recomputed here from each case's own `.probe` result and ledger
([derivation](evidence/2026-09-10-d158-split.json)); it reproduces D-158's 12 / 4 / 12 exactly.
`pytest-8399` is the 29th case and cannot be run at all (D-154).

## 2. What is held fixed, and the two things that are not

Held fixed: the population (not re-sampled), the clones, the plan file, `--budget 1.00`,
containers, `--code` pinned to one worktree at `b8d42f9`, local review only — no GitHub client is
constructed, so **no publication surface exists**.

Not held fixed, and this is the load-bearing caveat of the whole report:

1. **The recorded K=4 column was bought on 2026-09-06**, under `attest.intent.v4.1` and
   **before D-168**. It therefore had no 30% discovery ceiling, no candidate ranking and no
   per-unit verification cap: on `click 0585f456ba` it bought **9** reproductions where today's
   code buys **3**. A raw 4→5 diff would credit K with most of D-168.
2. **The code moved again after that**: D-174 (binding, `attest.intent.v4.2`), D-175–D-180.

So the third column is not "K=5, all else equal". It is **the shipped configuration as it
stands today**, which is the thing an outside repository actually gets, and that is the
question owner item 1 asked.

**One free column closes most of the gap.** D-168's own offline replay
([evidence](evidence/2026-09-08-schedule-replay-forward.json)) replays the **recorded K=4
candidates** under today's discovery share, ranking and per-unit cap. It is the *K=4, today's
schedule* arm, it costs `$0.00`, and its result is the reference point that makes the K=5
column readable:

| forward pairs | K=4, 2026-09-06 code (recorded) | **K=4, today's schedule** (free replay) | **K=5, today's code** (this run) |
|---|---|---|---|
| reproductions bought | 98 | **51** | *below* |
| receipts published | 3 | **3 — `receipts_lost: []`** | *below* |
| spend | $2.0313 | $1.0763 predicted | *below* |

**Because the middle column loses no receipt, a receipt the right-hand column loses is
attributable to K and not to D-168.**

## 4. The held-out 16: the run found a defect instead of a number

16 of 16 reviewed, `$1.6840`, largest single case `$0.2181`.
[Diff](evidence/2026-09-10-k5-heldout-diff.md).

**The raw column says certified 4 of 16 → 1 of 16. It is not a K result, and this report will
not report it as one.** Of the 27 verification verdicts the K=5 arm reached, **17 are
`probe deferred on base: missing or malformed JUnit evidence: ValueError: no JUnit artifact`**
(K=4: one), and every one of them is a `pytest-dev__pytest` case — 7 of the 9 in the sample.
`psf__requests` and `pylint-dev__pylint` are untouched.

**Three experiments, `$0.13`, and the attribution is settled:**

| run | K | code | `pytest-7324` |
|---|---|---|---|
| the arm itself | **5** | today | `no JUnit artifact` |
| re-run | **5** | today | `no JUnit artifact` — deterministic, not a flake |
| control | **4** | today | **`no JUnit artifact`** — so it is not K |
| control | 4 | `d058c58`, before D-174 | **`no JUnit artifact`** — so it is not this window either |

**What it actually is.** The reproduction image for those cases is built on **Python 3.12.14**,
and the project under review *is* pytest — a 2019–2022 tree whose assertion rewriter cannot
run there:

```
$ docker run --rm --entrypoint sh attest-repro:af29a7e315d2be74 \
    -c 'printf "def test_x():\n    assert True\n" > t.py && python -m pytest -q t.py'
ERROR t.py - TypeError: required field "lineno" missing from alias
!!!!!!!!!!!!!!!!!!!! Interrupted: 1 error during collection !!!!!!!!!!!!!!!!!!!!
```

**D-162 (2026-09-07) dropped 3.9 from the supported range** — `AVAILABLE_PYTHONS` is
`3.13, 3.12, 3.11, 3.10` and a declared floor below 3.10 gets the primary, 3.12. Its own
docstring says *"a project that cannot install on 3.10 is a bootstrap failure"*. This one
**installs fine** and then cannot collect, so it is not a bootstrap failure and gets no refusal
sentence: it surfaces as a missing artifact, which reads like a broken host. The K=4 held-out
column was bought on **2026-09-06**, the day before D-162 landed. **Every `pytest` case in this
corpus has been unreviewable since, and this run is what noticed.** Recorded as **D-185**; the
repair is not made here.

## 5. Yellow and green: K cannot move them, and the run confirms it

Yellow (a) (the impact scope), yellow (b) propagation and green (the structural measure) are
computed from `ast` and `git` over the two trees. Yellow (a) and propagation call **no model at
all**; green calls one only *after* its measure already holds, and only for wording. `K` is the
number of proposal samples the **red** discovery stage buys, so it cannot change what these
levels measure — and the run agrees:

| level | K=4 (offline scan, 2026-09-09) | **K=5 (this run's ledger rows)** |
|---|---|---|
| yellow (a), 11 forward pairs | **0** | **0** |
| yellow (b) propagation, 11 forward pairs | **0** | **0** |
| yellow (b) null/Optional | closed (D-169) — costs `$0.00` | closed |
| green, 11 forward pairs | not previously measured on this population | **4 notes** (2 in `click`, 2 in `more-itertools`) |

**Control noise is not in this report, and here is why.** The 126 null controls are not in the
27-review sample: at K=4 their verdicts are silences, K moves discovery rather than
adjudication, and 153 reviews at the `--budget` cap is **$153.00**. So **yellow (a)'s control
noise stays the 2026-09-09 figure, 1 of 68 (1.5%)**, taken free at today's code. It is
K-independent for the reason above, and the honest statement is that it was not re-measured at
K=5 rather than that it did not move.

**But K can silence a level it cannot move, and the two entry points disagree about that.** On
the pull-request path a review whose `deferred_reason` is set returns *before* `structural_notes`
and `impact_notes` are computed (`review/ci.py`), so a K=5 discovery DEFER takes green and both
yellows down with red. On the local path this run used, they are computed anyway
(`cli/main.py`, D-152/D-167). `click cd4674a6de` is exactly such a review: locally it still got
its green and yellow evaluation; through the Action it would have got none. That is recorded
here as an observation, not fixed — no author-visible surface is involved in this run.
